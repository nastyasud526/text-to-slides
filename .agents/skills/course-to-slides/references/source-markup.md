# Авторская разметка исходного текста

## Что считается разметкой

Разделяй два вида указаний в тексте урока:

- метки PowerPoint-шаблонов, включая `[тип: …]`, предлагают композицию обычного слайда;
- маркеры содержания называют упражнение, тест, вопрос, диалог или интерактивную механику.

Решение пользователя игнорировать метки PowerPoint-шаблонов не удаляет и не ослабляет маркеры содержания. Вопросы и интерактивности всё равно должны быть распознаны и переданы исполнителю iSpring.

## Сканирование до извлечения

До запуска содержательного извлекателя выполни `scripts/scan_source_markup.py <курс.docx> <source-scan.json> --lesson <id> --catalog <catalog.json>`. Сканер быстро читает структуру Word и показывает возможные метки, но не принимает смысловых решений. Оркестратор просматривает кандидатов, учитывает свободные формулировки вроде `[тип: …]`, `Шаблон: …`, `Макет: …`, «Закрепляющие вопросы» и другие фактические обозначения автора, затем создаёт `markup-audit.json`. Зафиксируй:

- общее число слайдов;
- однозначные позиции слайдов с авторской меткой шаблона: урок, локальный номер, сквозной индекс документа и исходный текст каждой метки;
- распознанный `templateId` или семейство, если соответствие однозначно;
- неизвестные и конфликтующие метки;
- однозначные позиции слайдов с маркерами вопросов, упражнений, диалогов и интерактивностей;
- покрытие разметкой: `none`, `partial`, `full` или `ambiguous`.

`ambiguous` используется, когда хотя бы одна метка неизвестна, конфликтует с содержанием или допускает несколько несовместимых толкований. Не применяй такую метку молча.

## Решение пользователя

Если меток PowerPoint-шаблонов нет, запиши автоматический подбор в `markup-decision.json` и не задавай лишний вопрос. Если метки есть, оркестратор показывает краткую сводку и спрашивает, какой режим применить:

- `use` — использовать все однозначные авторские метки как ограничения, а отсутствующие подобрать по смыслу;
- `ignore` — не учитывать метки PowerPoint-шаблонов и подобрать композиции заново.

Не проси пользователя исправлять JSON или вручную размечать каждый слайд. Неизвестные метки перечисли отдельно; даже в режиме `use` их должен разрешить смысловой исполнитель, сохранив предупреждение в отчёте.

После решения пользователя создай `markup-normalization.json`. Не изменяй исходный DOCX. Для принятой шаблонной метки запиши канонический `templateId`; для отдельного блока вопросов или интерактивности запиши начало нового синтетического слайда. Все записи ссылаются на устойчивый `bodyIndex` из сканера:

```json
{
  "version": 1,
  "sourceSha256": "<sha256 DOCX>",
  "templateMode": "use",
  "entries": [
    {
      "bodyIndex": 4,
      "kind": "template",
      "status": "accepted",
      "originalText": "Шаблон: text.illustration [низкая]",
      "templateId": "text.illustration"
    },
    {
      "bodyIndex": 35,
      "kind": "interaction_start",
      "status": "accepted",
      "originalText": "Закрепляющие вопросы",
      "interactionType": "quiz",
      "sourceSlide": 9,
      "title": "Закрепляющие вопросы"
    }
  ]
}
```

При режиме `ignore` шаблонные кандидаты получают `status: ignored`, но записи интерактивностей остаются принятыми. Передай карту извлекателю через `extract_docx_blocks.py <курс.docx> <source.json> --markup-map <markup-normalization.json> --lesson <id>`. Извлекатель исполняет каноническую карту, ограничивает выход выбранным уроком и не пытается угадывать произвольную авторскую формулировку.

Сохрани решение до создания `source.json`, `reading-ledger.json` и `lesson-plan.json`. В корне плана запиши:

```json
{
  "sourceMarkup": {
    "mode": "use",
    "templateCoverage": "partial",
    "templateMarkedSlides": [2, 5, 8]
  }
}
```

Исправленную копию Word создавай только по отдельной просьбе пользователя. Разметка является самостоятельным результатом. Запрос «только разметить» завершается после проверенного `lesson-plan.json` и не создаёт PPTX.
