# Жизненный цикл запуска

## Назначение

Состояние запуска сохраняет уже выполненную работу и позволяет продолжить создание презентации после исчерпания контекста, ошибки команды или отсутствия входного файла. Отдельная папка каждого запуска также предотвращает случайное использование планов и ассетов прошлых попыток.

## Сохранённые результаты

Для каждого запрошенного элемента фиксируются следующие результаты:

1. `initialized` — создана рабочая папка элемента;
2. `source_ready` — сохранены запрошенный материал и контекст, нужный для его понимания;
3. `plan_ready` — для всех запрошенных слайдов записаны решения и создан `lesson-plan.json`;
4. `assets_ready` — готовы ассеты, перечисленные в плане;
5. `presentation_built` — создан рабочий PPTX;
6. `verified` — структурная проверка завершена.

Этап готов, когда существует его ожидаемый результат и состояние зарегистрировано через `scripts/run_state.mjs`. Состояние описывает фактически готовые артефакты и не заменяет их проверку.

## Выбор запуска

Если пользователь прямо просит заново создать презентацию, не выполняй `run_state.mjs find` и не открывай данные предыдущих запусков. Создай независимый запуск через `run_state.mjs start --fresh`. В новом запуске работай только с исходным материалом, библиотекой, каталогом и результатами текущего запуска. Предыдущие планы, журналы решений, изображения, презентации, отчёты и другие результаты не являются входами или образцами для этой работы. Их не нужно признавать ошибочными: они просто не участвуют в новом запуске.

В остальных случаях до создания новой папки выполни `run_state.mjs find` для идентификатора курса и ключа запрошенного объёма. Если найдены прежние данные, покажи пользователю путь, дату, состояние и завершённые этапы. Пользователь решает, продолжать конкретный запуск или начать заново.

При продолжении используй только выбранную папку. Если пользователь отказался от найденных данных, создай независимый запуск через `run_state.mjs start --fresh`; если подходящих запусков нет, используй обычный `start`. Новая папка не получает планы, изображения и презентации прежних попыток. Если контрольные суммы исходника, библиотеки или каталога изменились, сообщи об этом до продолжения, поскольку сохранённые решения могли опираться на другую версию входов.

## Продолжение работы

После прерывания прочитай состояние выбранного запуска и результаты текущего этапа. Готовые результаты используются дальше, а работа продолжается с первого незавершённого результата.

Частично заполненный `decision-log.json` является сохранённым прогрессом планирования. Каждая запись фиксируется сразу после выбора композиции. При продолжении сохрани записанные решения и начни с первого запрошенного слайда, для которого отсутствует законченная запись. `plan_ready` устанавливается после того, как журнал содержит решения для всего запрошенного объёма и из них создан соответствующий `lesson-plan.json`.

Если диалоговая сцена отсутствует, создай эту сцену по сохранённому плану. Если сборка или структурная проверка завершилась ошибкой, повтори соответствующую команду с сохранённым планом и готовыми ассетами. Если отсутствует необходимый вход, сохрани состояние `waiting_for_input` с точным путём и причиной; после появления входа продолжи тот же этап.

## Команды состояния

Для команд используй Node, полученный через `load_workspace_dependencies`:

```text
<node> <skill-dir>/scripts/run_state.mjs find --results <results> --course_id <course-id> --scope_key <scope-key>
<node> <skill-dir>/scripts/run_state.mjs start --results <results> --course_id <course-id> --course_root <course-root> --scope_key <scope-key> --scope_label <label> --items <item-ids> --source <source> --template <template> --catalog <catalog>
<node> <skill-dir>/scripts/run_state.mjs start ... --fresh
<node> <skill-dir>/scripts/run_state.mjs set-stage --run <run> --item <item-id> --stage <stage> --status <status> --outputs <paths>
<node> <skill-dir>/scripts/run_state.mjs finish --run <run>
```

В `--items` передаются идентификаторы согласованного объёма, а в `--outputs` — созданные на соответствующем этапе файлы. Оркестратор обновляет состояние после получения результата от исполнителя и сообщает пользователю о `waiting_for_input` или `failed` с точным этапом, путём и причиной.
