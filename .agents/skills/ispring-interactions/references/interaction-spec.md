# Контракт интерактивностей

## Нормализованная заявка

Оркестратор добавляет в элемент `lesson-plan.json` объект `interactionSpec`. Он сохраняет исходный текст рядом с заявкой.

```json
{
  "type": "tabs",
  "title": "Что считается хорошим результатом",
  "intro": null,
  "items": [{ "title": "План", "body": "Сменное задание выполнено в срок." }],
  "outro": null,
  "sourceEvidence": ["Интерактив: вкладки по направлениям."]
}
```

Допустимые `type`: `quiz`, `steps`, `tabs`. В `sourceEvidence` сохраняются строки, на которых основано решение.

## Тест

```json
{
  "type": "quiz",
  "title": "Проверка решения мастера",
  "questions": [{
    "type": "multiple_choice",
    "prompt": "Как следует поступить мастеру?",
    "choices": ["Вариант 1", "Вариант 2"],
    "correct": [2],
    "feedback": { "correct": "Верно.", "incorrect": { "1": "Почему вариант 1 не подходит." } }
  }]
}
```

`multiple_response` хранит несколько номеров в `correct`. `matching` хранит `pairs`: массив объектов `{ "left": "…", "right": "…" }`. Поле `feedback.incorrect` может быть общей строкой либо объектом с пояснениями по номерам вариантов; во втором случае пояснения объединяются в общий текст неправильной обратной связи QuizMaker и сохраняются полностью. Одна заявка `quiz` создаёт один ресурс `.quiz` и один слайд теста независимо от числа вопросов.

## Шаги и вкладки

В `steps` и `tabs` каждый элемент содержит `title` и `body`. Сценарий не подставляет нумерацию автоматически, если автор указал собственное название шага. Изменение количества элементов разрешено только после проверки конкретного сгенерированного варианта в PowerPoint и iSpring.

## Неопределённость

Если блок похож на интерактивность, но его механику нельзя отнести к трём поддерживаемым типам, запиши в `ispring-unresolved.json` объект с `sourceSlide`, `sourceText`, предполагаемой причиной и обнаруженными авторскими пометками. Не пытайся заменить его обычным текстовым слайдом или другой механикой.
