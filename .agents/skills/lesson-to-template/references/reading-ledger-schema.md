# Схема реестра чтений

## Назначение

`reading-ledger.json` сохраняет смысл и структуру исходных слайдов до открытия каталога шаблонов. Он отделяет понимание текста от выбора композиции и не содержит групп, `templateId`, полей шаблона или решений по раскладке.

Реестр включает только слайды, для которых позднее выбирается композиция `kind: content`. Титульный и диалоговый слайды не входят в него. Интерактивный содержательный слайд входит на общих основаниях.

## Структура

```json
{
  "version": 1,
  "lessonTitle": "Название урока",
  "slides": [
    {
      "sourceSlide": 1,
      "sourceText": "Дословный видимый текст слайда",
      "reading": {
        "function": "Учебная функция материала.",
        "keyMessage": "Мысль, которую должен понять обучающийся.",
        "units": [
          {
            "text": "Дословный фрагмент исходника",
            "role": "context | claim | cause | effect | side | step | condition | example | application | conclusion",
            "level": "framing | core | support"
          }
        ],
        "framing": {
          "intro": ["Дословные фрагменты введения"],
          "conclusion": ["Дословные фрагменты вывода"]
        },
        "relationships": {
          "primary": {
            "type": "comparison | cause-effect | sequence | complementary | composition | classification | rule-example | situation-solution | none | uncertain",
            "evidence": ["Дословные фрагменты, подтверждающие связь"],
            "whyPrimary": "Почему эта связь необходима для понимания вывода."
          },
          "secondary": [
            {
              "type": "Тип вторичной связи",
              "evidence": ["Подтверждающие фрагменты"],
              "whyPresent": "Какую вспомогательную роль она выполняет."
            }
          ]
        },
        "excludedNotes": ["Служебные производственные пометки"]
      }
    }
  ]
}
```

`units[].text`, `framing` и `evidence` сохраняют формулировки исходника. `keyMessage`, `whyPrimary` и `whyPresent` являются аналитическими записями и не переносятся на слайд как видимый текст.

## Перенос в lesson-plan.json

Для итогового `reading` используй детерминированное представление записи реестра:

- `function` — без изменений из реестра;
- `units` — значения `units[].text` в исходном порядке;
- `relationships` — строка `Главная связь: <type>. <whyPrimary>`, дополненная вторичными связями при их наличии;
- `excludedNotes` — без изменений из реестра.

`review_plan.mjs` строит то же представление и отклоняет план, если фаза выбора изменила чтение или `sourceText`.

## Сложная структура

Сначала отдели введение и вывод как рамку. Главную связь выбирай среди единиц уровня `core` по тому, какая связь необходима для понимания вывода. Если вывод объясняет результат, используй `cause-effect`; если фиксирует различие сторон — `comparison`; если зависит от порядка — `sequence`; если объединяет обязательные элементы — `composition` или `classification`. Остальные связи сохраняй как вторичные.

Если главную связь нельзя определить по исходнику, используй `uncertain`. Такой слайд не переходит к выбору шаблона до повторного чтения.
