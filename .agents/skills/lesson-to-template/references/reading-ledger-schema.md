# Схема реестра чтений (версия 2)

## Назначение

`reading-ledger.json` сохраняет ответы анкеты по каждому содержательному слайду до открытия каталога. Он не содержит групп, `templateId`, полей шаблона или решений по раскладке. Титульный и диалоговый слайды в него не входят; интерактивный содержательный слайд входит.

## Структура

```json
{
  "version": 2,
  "lessonTitle": "Урок 1.3. Как ведёт себя мастер",
  "slides": [
    {
      "sourceSlide": 9,
      "sourceText": "Дословный видимый текст слайда",
      "authorType": null,
      "reading": {
        "function": "Учебная функция слайда одной фразой.",
        "keyMessage": "Мысль, которую должен понять обучающийся.",
        "answers": {
          "chain":      { "answer": true,  "links": ["Мастер кричал на весь цех", "Рабочие боялись подходить", "не уточняли задания и скрывали проблемы", "Работа останавливалась, ошибки накапливались"], "outcome": "сильные рабочие начинали увольняться" },
          "sides":      { "answer": false },
          "research":   { "answer": false },
          "list":       { "answer": false },
          "definition": { "answer": false },
          "example":    { "answer": false },
          "conclusion": { "answer": true,  "evidence": ["Строгость удерживает понятное требование. Давление заставляет человека защищаться…"] }
        },
        "intro": ["Другая ошибка — добиваться результата криком и угрозами."],
        "primary": "chain",
        "whyPrimary": "Без цепочки не понять, почему давление вредит участку."
      }
    }
  ]
}
```

Поля ответов:

- `chain`: `links` (звенья по порядку, дословно), `outcome` (чем закончилось).
- `sides`: `kind` (`poor-good` или `two-sides`), `left`, `right` (дословные фрагменты каждой стороны), `intro` при наличии.
- `research`: `evidence` (исследование или факт), `conclusion` (вывод для мастера).
- `list`: `count`, `ordered` (true для шагов), `named` (есть ли у элементов названия), `items` (дословно).
- `definition`: `evidence`.
- `example`: `evidence`.
- `conclusion`: `evidence`.

`primary` принимает одно из значений: `chain`, `poor-good`, `two-sides`, `research`, `steps`, `items`, `definition`, `example`, `text`. Приоритет при нескольких `да` задан в SKILL.md; `primaryFromAnswers` в `scripts/bridge.mjs` вычисляет то же самое, и `review_plan.mjs` проверяет совпадение.

`authorType` переносится из тега `[тип: …]` в исходнике. Если он задан, `primary` обязан ему соответствовать.

## Перенос в lesson-plan.json

`reading` в плане строится детерминированно:

- `function` без изменений;
- `units`: все дословные фрагменты из положительных ответов в порядке вопросов;
- `relationships`: строка `Главная связь: <primary>. <whyPrimary>`;
- `excludedNotes`: пустой массив (пометки автора вырезаются до чтения).

`review_plan.mjs` строит то же представление и отклоняет план, если фаза выбора изменила чтение или `sourceText`.
