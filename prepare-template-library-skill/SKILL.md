# Подготовка библиотеки шаблонов

Используй этот навык только тогда, когда пользователь явно просит подготовить, проверить, мигрировать или заново собрать библиотеку шаблонов курса либо её каталог. Это отдельная операция по проектированию и настройке курса. При обычной сборке урока библиотека считается готовой и используется навык `../lesson-to-template-skill`.

## Граница действий

Подготовка библиотеки меняет общую инфраструктуру курса. До редактирования назови точные PPTX, каталог, метаданные, скрипты и файлы навыков, которые изменятся, затем дождись явного подтверждения. Обсуждение, диагностика и неудачный preflight урока не разрешают исправлять библиотеку.

## Результат

Создай одну подготовленную библиотеку PPTX и один соответствующий семантический `catalog.json`. Каждый переиспользуемый физический слайд содержит устойчивый `template_id` в заметках докладчика или комментарии, уникальные имена редактируемых полей и запись каталога, которая обычным языком объясняет его учебное назначение.

Каталог должен помогать другой модели принимать осмысленные решения. Для каждой композиции он описывает, что она помогает понять обучающемуся, какие семантические части предлагает, какова её относительная плотность, и приводит один короткий пример. Не превращай ошибки пилотных запусков в универсальные запреты, оценки или жёсткие ограничения по количеству символов.

## Проектирование каталога

До подробных композиций создай компактный индекс `groups`. Группы сужают поиск при планировании урока, но не задают универсального порядка приоритетов. Шаблон может входить в несколько групп, если действительно поддерживает несколько учебных структур.

Для каждой семантической композиции поддерживай:

- `templateId`: устойчивый физический идентификатор;
- `groups`: одно или несколько широких семейств;
- `description`: что визуальная структура помогает понять обучающемуся;
- `example`: один краткий показательный пример, который не служит ограничивающим правилом;
- `slots`: семантические поля, сопоставленные с точными именами объектов PowerPoint;
- технические поля `kinds`, `runStyles`, `imageSlots` или `stripToSlots` только тогда, когда они нужны сборщику.

Используй относительные обозначения вроде «короткий», «средний» или «подробный», если визуально родственные шаблоны различаются плотностью. Не добавляй автоматическое уменьшение шрифта или жёсткие пороги вместимости, пока пользователь не запустит отдельный проход настройки этих параметров.

## Процесс

1. Загрузи встроенную среду для презентаций и структурно проверь текущий PPTX. Запусти `scripts/inspect_templates.mjs <template.pptx> <inventory.json>`; добавляй `--render-dir` только тогда, когда пользователь явно просит визуальное ревью шаблонов или визуальное свидетельство необходимо для понимания изменившейся композиции.
2. Сравни физическую библиотеку с предыдущим каталогом. Определи добавления, удаления, перестановки, дублирующиеся идентификаторы, отсутствующие имена и изменённые поля. Не смешивай эту работу со сборкой урока.
3. Сохрани пользовательский визуальный дизайн. Переименовывай только редактируемые объекты, которым нужны устойчивые семантические имена. Для детерминированного переименования используй `scripts/rename_template_text_fields.mjs`.
4. Создай или обнови семантический каталог. Используй текущий физический порядок слайдов, компактные группы, описания, примеры и точные именованные поля.
5. Примени устойчивые метаданные заметок и согласованные удаления слайдов через `scripts/apply_catalog_to_library.mjs`. Сначала записывай новый выходной файл; не перезаписывай исходник до проверки.
6. Повторно проверь результат и запусти пользовательский preflight из `../lesson-to-template-skill/scripts/preflight_library.mjs` для итогового каталога.
7. Заменяй назначенную библиотеку только после успешной структурной проверки подготовленной копии. Сообщи обо всех удалённых или заменённых шаблонах и итоговом количестве слайдов.

## Технические границы

- Используй устойчивые значения `template_id` и именованные объекты PowerPoint вместо числовых индексов фигур.
- Сохраняй тему, образцы, макеты, геометрию, типографику, медиаресурсы и несвязанные заметки.
- Удалённый или заменённый шаблон должен одновременно исчезнуть из PPTX, индекса групп, семантических композиций, примеров и проверочных фикстур.
- `staging.blank` и `staging.interaction` являются отдельными физическими шаблонами, потому что при сборке урока для них выполняются разные операции.
- Визуальный рендеринг относится только к этому явному процессу подготовки, когда он запрошен или нужен для неоднозначного шаблона. Он не становится частью каждой сборки урока.

При создании или проверке реестра используй [структуру каталога](references/catalog-schema.md).
