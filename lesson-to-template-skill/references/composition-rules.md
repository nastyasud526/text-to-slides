# Composition selection

Use agreed formal markup such as `layout:` first. Free-form notes in the lesson source are provisional production comments, not commands. A note such as `Визуал:` or `Интерактив:` is evidence to consider alongside the actual content structure and density. Template-slide comments and speaker notes describe what an existing composition was designed to hold, but still verify them against its named fields and rendered slide.

When the source has no formal format, classify its teaching purpose: speaker-labelled exchange is dialogue content; equal independent points suggest cards or columns; comparison suggests a contrast template; a concrete incident plus a conclusion suggests a case template; a term or governing statement followed by explanation suggests definition-and-explanation; a sequence suggests a process; observable criteria suggest a list or checklist depending on whether they are descriptions or actions.

If no exact composition fits, compare the closest existing compositions and record why each fails. Use title-and-text only when the prose genuinely has no stronger structure. When the prose has a clear key idea that deserves emphasis but the catalog has no suitable emphasis composition, record a template gap for a future template instead of repeatedly flattening such slides into title-and-text. Do not invent a layout ID from an item count. Preserve approved wording unless the user has explicitly accepted an editorial adaptation.

For a speaker-labelled dialogue, use the dedicated `dialogue.scene` template in the current library. It contains the named full-slide image `DIALOGUE_SCENE`, the left Alexey bubble, and the right Denis bubble. Resolve its `image_prompt:` before generation: preserve an author-supplied prompt, or create one from the slide using [dialogue-image-prompt.md](dialogue-image-prompt.md). The returned 16:9 scene includes both Alexey and Denis, even when only one has a spoken line on this slide. The plan records `scenePath`; the common batch builder replaces `DIALOGUE_SCENE` and writes the two bubble fields. For a lesson note marked as interactive, first ask whether all approved content can fit an existing static composition and whether reveal, branching, answer checking, or state changes are essential. Prefer the static composition when it fits. Use interaction staging only when text density exceeds one static slide or the mechanic is essential.

One physical template may support several semantic uses. Record them in `kinds` and keep one stable `templateId`; do not duplicate catalog entries merely to express alternative uses. A composition such as introduction-main-conclusion may therefore also be a temporary fit for situation-actions-result, provided the decision log records that mapping and any missing dedicated template.

For every slide decision, record the chosen composition, intended field mapping, rejected alternatives, the effect of any source comment, confidence, and template gaps. Low confidence or the absence of an honest composition is a stopping condition before PPTX generation. When several valid compositions fit, prefer the least recently used compatible variant after matching teaching purpose, item count, and density.

Capacity is advisory. Prefer the composition whose semantic structure matches the material, then record any overflow risk. Do not replace a comparison of equivalent or parallel dimensions with a good-versus-bad layout solely because its columns are larger.

When a mapped field contains several source run styles, preserve their semantic hierarchy. Put a short term, lead-in, or key conclusion fragment into the accent style and the explanatory remainder into the body style. The selected fragment must carry the main emphasis; do not color or enlarge the entire replacement merely because the first template run is accented.
