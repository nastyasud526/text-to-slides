# Lesson to Template

Use when the user supplies a prepared PowerPoint library, its matching catalog, and lesson text and wants a new deck assembled from copies of those slides. Template-library preparation is outside this skill.

## Action boundary

Treat questions, discussion, comparison of options, requests for an explanation, review, or diagnosis as discussion only. They do not authorize editing files, changing the skill, rebuilding a presentation, overwriting an artifact, or running a pipeline that creates output. Before any such action, state the exact proposed change and affected artifacts, ask for explicit confirmation, and wait for it.

An explicit imperative in the current user message, such as `внеси правило`, `исправь код`, `собери презентацию`, or `пересобери файл`, is confirmation only for the named action. Do not extend it to adjacent improvements. When the message expresses doubt, explores alternatives, or asks why something happened, answer and discuss the options first.

## Decision ownership

Read the complete lesson once before choosing compositions. For DOCX sources, first create a deterministic source ledger with `scripts/extract_docx_blocks.py`; it reads body elements in document order and includes paragraphs inside tables, text boxes, content controls, headers, and footers when they contain lesson content. `document.paragraphs` alone is not a complete extraction. Reuse the supplied catalog exactly as prepared. Dialogue slides bypass general composition selection and use the first blank library slide through the `staging.blank` exception. Interaction staging uses the separate physical clone `staging.interaction`. Scripts do not infer teaching structure or choose layouts: they copy mapped slides, write text into named fields, and verify the output structurally.

Treat a slide's PowerPoint comment or speaker note as its design brief. A reusable slide needs a stable line `template_id: meaningful.id`; the remaining text may describe composition, density, restrictions, and intended use in ordinary language. The user owns visual design and those comments. You own the catalog, semantic field mapping, lesson plan, and technical checks.

Keep a template image or illustration as its existing placeholder unless the user explicitly asks to replace it. A recognised dialogue slide is an exception: always duplicate the first blank slide registered as `staging.blank`, call `../veza-dialogue-scenes` once for that slide, and insert the returned 16:9 PNG as the full-slide `DIALOGUE_SCENE`. The generated PNG contains characters and environment only. Put the speaker-labelled replicas into the blank slide's existing editable text field; do not create or display a title, speaker labels, speech bubbles, captions, callouts, or other course text over the scene. Finding a dialogue slide must not trigger a scan or comparison of the general template catalog and must not require a dedicated physical dialogue template.

## Prepared-library boundary

This skill never creates, edits, inspects, migrates, or refreshes a template library or its catalog. Those are one-time course-design operations handled outside lesson assembly. At the start of every run, execute `scripts/preflight_library.mjs <template.pptx> <catalog.json>`. The preflight reads only PPTX metadata and checks slide count, `template_id` placement, and mapped object names. If it fails, stop and report the exact mismatch. Do not run `inspect_templates.mjs`, rename fields, modify the PPTX, modify the catalog, or continue building unless the user separately requests library preparation.

The catalog addresses a composition by `templateId` and each text slot by PowerPoint object name, never by a numerical shape index. See [catalog schema](references/catalog-schema.md).

## Content contract

- Preserve approved course wording. You may distribute one source block across the selected template's fields and make a small structural rearrangement without changing its wording when that makes the slide's meaning clearer, for example by moving a concluding sentence into an introductory position. Do not shorten, rewrite, or add content unless the user explicitly accepts editorial adaptation.
- Treat formal layout markup such as an agreed `layout:` field as authoritative. An `image_prompt:` attached to a dialogue slide is also authoritative for the semantic content of its scene. Treat free-form production notes inside the lesson source, including `Визуал:` and `Интерактив:`, as draft hints that may be stale or noisy. Judge the actual text structure and available template capacity before following them.
- If no exact template fits, first adapt the material to an existing composition. Use an available title-and-text template only when that is the closest honest fit, and record the choice in the lesson plan.
- Classify the slide by its teaching meaning rather than by the presence of numbers, bullets, or a convenient field set. Consider the more specific meanings first: service/title, true character dialogue, interaction, statistics, comparison, end-of-lesson checklist, and process or development of a situation. Then consider a list, cards, or classification. Use a text composition for theory, explanation, example, production situation, research with conclusion, or problem-explanation-solution when no stronger structure is present.
- Treat numbered and marked lists as one semantic group. Numbering is a presentation choice and does not by itself make material a process. Keep `checklist` separate: use it only for an actual self-check or end-of-lesson checklist.
- A process is a temporal, causal, operational, or situation-development relationship. Prefer a process, timeline, or connected-elements composition when that relationship is the point of the slide. A numbered-list composition is an acceptable fallback when it represents the process more honestly at the available text density; do not route an ordinary list into a process composition merely because its points are numbered.
- Use an introduction-and-cards composition only when the source already has a short introductory thought followed by independent, homogeneous elements. Do not split a coherent explanatory paragraph into cards to fill available slots.
- Before choosing a candidate, estimate the source's density: the length and number of independent text blocks, the role of each block, and the available room described by the template brief, fields, and catalogued capacity where it exists. Use this estimate to reject plainly unsuitable variants, while preserving the semantically correct group. For `staging.interaction`, do not reject the route because its source text is long when an approved interactive will contain, reveal, or otherwise distribute that text.
- When two or more templates fit the same meaning and density, choose the compatible variant used least often earlier in the current deck. Apply this to processes, lists, cards, columns, and similar repeated compositions; consider required fields and density before variety.
- For a process, timeline, numbered list, or marked list, leave unused item fields empty when the template has more slots than the source needs. When the source has more items than the selected template can hold, fill the available slots in source order and record the remaining items in that output slide's speaker notes under `ДОВЕРСТАТЬ ВРУЧНУЮ`, with the selected template ID and the reason. A closer process or timeline composition may still be chosen despite this overflow.
- Treat a true dialogue as a speaker-labelled character comment on theory. Route it directly to `staging.blank`; do not search, rank, or compare it against general catalog compositions. Dialogue wording inside an example, case, or production situation does not by itself make the slide a dialogue slide. Preserve the dialogue wording and resolve an `image_prompt` before invoking `../veza-dialogue-scenes`: use the author's prompt when supplied; otherwise create one from the slide meaning by the guide in [dialogue-image-prompt.md](references/dialogue-image-prompt.md). The image skill sanitizes either prompt and removes requests for headings, dialogue text, speech bubbles, captions, labels, callouts, plaques, and other course text before generation. The scene always contains Alexey on the left and Denis on the right, including a continuation where only one has a spoken line. Do not route dialogue through a decorative title-and-text composition or a separate physical dialogue template.
- Treat an exercise question with answer options, sorting, matching, or another explicit exercise mechanic as interaction staging; route it directly to `staging.interaction`, never to `staging.blank`. Put the complete approved source block into its mapped `body` slot. When the lesson explicitly calls for tabs, a marked image, or another interactive mechanic that is not an exercise, decide whether the mechanic makes understanding or practice materially better than an ordinary static slide. Use `staging.interaction` when it does; otherwise select the strongest static composition.
- Before building, keep a slide-decision log with the selected composition, field mapping, rejected alternatives, reasoning, confidence (`high`, `medium`, or `low`), and any template gap. Stop for user review when confidence is low or no honest composition exists. Do not create a PPTX while unresolved decisions remain.
- When prose contains a clear key idea but no list, cards, comparison, process, example, or other registered structure, check for a key-idea or emphasis composition. If none exists, record a template gap instead of silently routing repeated slides to title-and-text.
- Treat slot limits as advisory. Choose the semantically correct composition after estimating density; do not switch to a less accurate composition solely because it has larger text boxes. Do not change font sizes automatically. Record a declared capacity risk for manual review while preserving the wording, layout, and slide count.
- Make a separate title slide from the catalogued title template. Uppercase every semantic heading field: `title`, `subtitle`, and fields ending in `_title` or `_label`. Preserve the casing of body, definition, explanation, and other non-heading fields.
- Preserve intentional mixed formatting inside an editable field. When a template field contains an accent run followed by a body run, put only the meaningful term, lead-in, or conclusion fragment into the accent segment and keep the remaining text in the smaller body segment. Never apply the first run's color, font, or size to the whole field.

## Workflow

1. Set `RUNTIME_NODE_MODULES` to the bundled Node packages directory reported by `load_workspace_dependencies`.
2. Run `scripts/preflight_library.mjs <template.pptx> <catalog.json>`. If the prepared library and catalog do not match, stop and ask the user whether to start a separate library-preparation task. Never repair or refresh them inside this skill.
3. Read the complete `.docx`, `.md`, or `.txt` lesson source. For `.docx`, run `python lesson-to-template-skill/scripts/extract_docx_blocks.py <source.docx> <source-ledger.json>` once and use the ledger as the source of truth for the planning pass; it traverses the document body in order, including ordinary paragraphs, every table cell, nested text, content controls, headers, and footers. Use the Documents skill only when a visual or non-text inspection is actually needed. Never treat `document.paragraphs` as the complete source because it omits paragraphs inside tables. Create and review the slide-decision log, resolve every low-confidence choice or template gap, and only then create the internal version-2 `lesson-plan.json`; the user never prepares it.
4. For every dialogue slide, set `composition` to `staging.blank` and resolve `image_prompt` before image generation. If the source contains an author prompt, preserve its semantic scene decision; if it does not, create the prompt from the dialogue and slide meaning using [dialogue-image-prompt.md](references/dialogue-image-prompt.md). Invoke `../veza-dialogue-scenes`, which sanitizes the prompt and makes one generation call. Save the returned scene path, sanitized prompt, and speaker-labelled `dialogue` array in the internal lesson plan. Do not run a separate model-based image review or automatic regeneration.
5. Run `scripts/build_presentation.mjs <template.pptx> <catalog.json> <lesson-plan.json> <output.pptx>`. It duplicates only mapped template slides and replaces text inside existing styled `<a:r>` elements. Plain string values preserve the first run style. A structured value with `segments` selects catalogued run styles and preserves each chosen run's `<a:rPr>`; this supports a highlighted term followed by smaller body text in the same shape. The builder must never recreate ordinary template text boxes or call a high-level `text.set`. The dialogue exception duplicates `staging.blank`, removes its placeholder, inserts the generated PNG as a full-slide `DIALOGUE_SCENE`, and fills the existing editable staging text field with the speaker-labelled replicas. It must not create a title, speech bubbles, speaker labels, or other overlay objects. Each dialogue slide receives a separate media relationship. Interaction staging duplicates `staging.interaction`, keeps its mapped `body` field and inherited background, and removes other slide-local objects through `stripToSlots: true`.
6. Run `scripts/verify_output.mjs <output.pptx> <catalog.json> <lesson-plan.json> <verification-directory>`. It verifies slide count, exact text by named object, heading casing, and the hash of every embedded dialogue scene. Lesson assembly does not render slides, create PNG previews, or perform visual review.

Use one source extraction, one decision pass, one build, and one structural verification pass. Do not retry an optional tool after failure and do not perform adjacent repairs. A normal lesson run with a prepared library should finish within ten minutes.

## Limits

- Mixed-style replacement reuses styles already present in the template field. It does not invent a new typeface, color, size, or emphasis that the source shape does not contain.
- `template_id` values must be unique. A missing or duplicated marker is a catalog error, because the system must not guess which slide represents a template.
- Object names must be unique within a slide. If PowerPoint has duplicated a name, rename the conflicting editable objects before mapping them.
